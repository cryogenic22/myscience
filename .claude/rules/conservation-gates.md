# Conservation Gates & Operating Discipline

*The harness floor for Market Zero. Read this before shipping anything — it binds
every role: **builder, data, devops, reviewer**, and every sub-agent.*

> **The one line:** never let "the job ran" or "the build passed" equal "the
> product is healthy."

This is a **principle-transplant** of ADR-0003 (from the Content_medical_hub
repo) onto market_zero's *native* primitives — not a copy of its machinery (no
contract_runner, frozen packs, CCR, or `CK_ACTOR_ROLE`). The disease is shared;
the dominant, repeatedly-realised form here is **#2 silent data degradation**
("the dossier feels hardcoded" — a 0-fact duplicate selected; every fact
rendered as `signal` because `fact_class` wasn't selected; feeds 105 days stale
while logging SUCCESS).

## The four principles

1. **Separation of authorship.** You do not edit the bar to pass. The
   success-definition surface is listed in `protected-surface.txt`; route
   bar-changes through the owner (say so in the PR), never a silent self-edit.
2. **Conservation before correctness.** Freshness / linkage / orphan /
   no-silent-loss invariants make the cheap degradation path *fail closed*. A
   resolve/consolidate/compress/coerce step must never drop rows, fields, or
   provenance silently — soft-delete (`record_status='superseded'`, reversible),
   record a drop-manifest, or log the count.
3. **No vacuous green.** A gate that checks nothing fails closed. An empty
   suite, an all-skipped run, a typecheck of 0 files, a tolerated-error
   allowance with no expiry — all read as "covered" while covering nothing.
4. **Structural floor over discipline.** CI gates + CODEOWNERS/branch protection
   are the floor; this doc, the hooks, and CLAUDE.md are the ceiling. Prefer the
   floor; state plainly when something is only the ceiling.

## The two lanes (keep them separate)

Mixing live checks into PR gates trains everyone to ignore red. Keep the split:

| Lane | Checks | Runs | Where |
|---|---|---|---|
| **Lane 1 — deterministic** | seeded/DB-free invariants: fact_class-loss, resolver-picks-richest, predicate visibility, schema-floor logic, no vacuous typecheck, protected-surface sync | every PR + push | `.github/workflows/conservation-gate.yml` (HARD) |
| **Lane 2 — operational** | live `connector_health.py`, SLA/freshness, FK-orphan ceilings, evidence floor, 0-row anomalies | daily cron + release + dispatch | `.github/workflows/operational-health.yml` (HARD; needs `DATABASE_URL` secret) |

A live source being down must **never** red a PR — that belongs in Lane 2. And
the 105-day-stale failure was a *runtime* event no PR gate could catch; Lane 2 is
where the dominant failure actually lives. **Lane 2 fails loudly if
`DATABASE_URL` is missing** — a skipped health gate is itself a vacuous green.

## Definition of Done (every role, every loop)

A unit of work is DONE only when ALL hold — else it is PARTIAL, say so:

1. A test fails without the change and passes with it (RED→GREEN).
2. The passing command **and its pasted output** are in the close-out. "Committed" ≠ "Done". **Never claim a result from memory or fabricate a figure.**
3. Lane-1 deterministic gate is green; touched-surface typecheck/lint clean.
4. No conservation invariant regressed; no protected-surface file was edited to pass (if the bar genuinely must move, that is a separate owner-reviewed change).
5. For data work: a real prod probe (`scripts/probe_substrate.py` / `connector_health.py` / a SELECT) confirms the before→after, pasted.
6. An **independent** reviewer pass confirms it (see below) — not the same agent reviewing its own diff.

## Adding a new gate? Couple protection with hardening — same change

When you make a check HARD, add its definition file to `protected-surface.txt`
and regenerate CODEOWNERS **in the same commit** (`python
scripts/gen_codeowners.py`). A hard gate a builder can edit just relocates the
Goodhart. `tests/test_protected_surface_sync.py` enforces the sync.

## Roles

- **Builder / worktree agent:** set `export MZ_ACTOR_ROLE=builder` and
  `git config core.hooksPath .githooks` so the advisory pre-commit engages. You
  implement against the bar; you do not move it.
- **Data agent:** conservation invariants are yours to *strengthen* (tighten a
  ceiling after a real fix, add a new freshness SLA) via an owner-reviewed
  change — never *loosen* to pass. New connector ⇒ a `FRESHNESS_SLA_DAYS` entry
  ⇒ Lane-2 covers it automatically.
- **DevOps:** own the Lane-2 schedule + the `DATABASE_URL` secret + (server-side)
  branch protection requiring CODEOWNERS review and the conservation-gate check.
  You configure enforcement; you do not author the gates.
- **Reviewer:** structurally separate, adversarial — see `/review-gate`.

## Owner actions (server-side, one-time — the real floor)

1. Add repo secret `DATABASE_URL` (Railway URL) so Lane 2 can run.
2. Branch protection on `main`: require CODEOWNERS review, the
   `Conservation Gate (Lane 1 — deterministic)` check, and disallow self-approval.
3. Decide the connector status-emission rollout (next loop — see below).
