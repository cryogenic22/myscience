## 3. The Contract: OpenAPI as Single Source of Truth

The boundary between backend and frontend is the **REST API**, defined by:

- **Live spec**: `GET /openapi.json` (FastAPI auto-generated)
- **Snapshot in repo**: `schema/openapi.json` — Claude regenerates on every
  API-changing PR via `python -m scripts.snapshot_openapi`

### When Claude changes the API
1. Implement the change.
2. Regenerate `schema/openapi.json` snapshot.
3. Append entry to `docs/API_CHANGELOG.md` (template in §4).
4. **Backwards-compatibility window**: keep deprecated endpoints alive for
   ≥1 release cycle (~14 days). Mark `deprecated: true` in OpenAPI.

### When Antigravity needs a new endpoint
1. File request in `docs/AGENT_BACKLOG.md` under `[BACKEND]` with: surface, payload
   shape needed, why current endpoints don't suffice.
2. Do NOT mock/fake the call in `api.ts`. Wait for Claude to ship.
3. Once shipped (visible in `API_CHANGELOG.md`), add typed client method to
   `frontend/src/api.ts`, then build UI.

### When Antigravity needs a payload tweak
- Additive (new field): file `[BACKEND]` request, low priority.
- Breaking (rename/remove): file `[BACKEND]` request, high priority, propose
  the new shape. Claude responds in changelog or backlog.

## 5. Cross-Cutting Specs

Some features cross the boundary (e.g., a new "Workspace Snapshots" feature
needs DB schema + API + UI). These need a shared spec.

### Spec workflow
1. Initiator writes a short spec at `specs/SPEC_NNN_<feature>.md` using the
   template (next number after the latest existing spec).
2. Spec must include: **Goal**, **Backend changes** (tables, endpoints,
   payloads), **Frontend changes** (surfaces, components, flows), **Open
   questions**.
3. Other agent reads, posts replies inline as `> [Antigravity] ...` /
   `> [Claude] ...` quote blocks.
4. Once both agents have signed off (`✓ Signed off by <agent>` line at top),
   each implements their half on their own branch.
5. Coordinate landing order via a `Land order:` section (usually backend first,
   then frontend).

## 6. Branching & PRs

| Concern | Convention |
|---------|------------|
| Branch prefix | `claude/*` for backend; `antigravity/*` for frontend |
| Cross-cutting | `spec/SPEC-NNN-*` (initiator branches first, other rebases on top) |
| PR labels | `area:backend`, `area:frontend`, `area:full-stack` |
| PR template | Must include "Other-side impact: none" OR link to spec/changelog entry |
| CI | Backend tests run on `*.py` changes; frontend tests run on `frontend/**` changes |
| Merge | Squash merge. Conventional commit format (`feat:`, `fix:`, `chore:`). |
| Auto-deploy | `main` → Railway (full stack). Both agents responsible for not breaking deploys. |

### Conflict resolution
- If both agents need to touch the SAME file (e.g., `specs/SPEC_021.md`),
  whoever opens a PR first wins. Other rebases.
- If a backend change forces a frontend break with no deprecation window
  (rare), Claude **must** open a PR against `frontend/src/api.ts` updating
  types only, with `[CLAUDE-HOTFIX]` in commit message. Antigravity reviews
  next session.

### Design rules (non-negotiable, from CLAUDE.md)
- ✅ Use CSS custom properties (`var(--color-ink)`, `var(--color-surface)`)
- ✅ Inline styles for layout-critical surfaces (NOT Tailwind utility classes
  for colors — `bg-slate-*`, `text-slate-*` are banned)
- ✅ Fraunces (display, serif) + DM Sans (body, sans). For technical/numeric
  surfaces, DM Mono is preferred (see `specs/test.tsx`).
- ✅ Dark mode via `@theme` token switching, NOT `!important` overrides
- ❌ NEVER call `useMemo` inside `.map()` loops — caused production React
  error #310 last quarter
- ❌ NEVER duplicate utilities — check `.claude/rules/anti-slop.md` first
- ✅ TDD with Vitest for new components: `frontend/__tests__/<dir>/<name>.test.tsx`

### Backend API surfaces Antigravity must know
| Surface | Purpose | Key endpoints |
|---------|---------|---------------|
| Inbox | Agentic landing — pending proposals, overdue decisions, signals, calibration | `GET /inbox` |
| Insights | Calibration trend + outcome stream | `GET /insights` |
| Decisions | Decision flywheel CRUD + outcome capture | `GET /decisions`, `POST /decisions/from-round`, `POST /decisions/{id}/capture-outcome`, `GET /decisions/{id}/full` |
| War Rooms | Move-suggester + scoring + comments | `POST /war-rooms`, `GET /war-rooms/{id}`, `POST /war-rooms/{id}/comments` |
| Signals | CI signal feed | `GET /signals` (cursor-paginated) |
| Chat | Conversational orchestrator | `POST /chat`, `POST /chat/stream` |
| Catalog | Data browse + curation | `GET /catalog/datasets`, `GET /catalog/entities` |
| Auth | JWT-based | `POST /auth/login`, `POST /auth/register` |

### Auth conventions
- JWT stored in `localStorage.mz_auth_token`
- Role stored in `localStorage.mz_auth_role` (`viewer` / `editor` / `enterprise`)
- All protected calls: include `Authorization: Bearer <token>` header
- 401 → redirect to login; 403 → show "insufficient role" message
- Standard error envelope: `{ error: { code, type, message, details } }`
  (also includes `detail` for backwards compat)
- Rate limit: handle 429 with `Retry-After` header

### Definition of Done for any frontend PR
- [ ] Vitest tests added for new components
- [ ] No hardcoded colors — design tokens only
- [ ] No new utilities duplicating anything in anti-slop catalog
- [ ] Lighthouse a11y score ≥95 for changed surfaces
- [ ] Tested in light AND dark mode
- [ ] `frontend/src/api.ts` types match `schema/openapi.json`
- [ ] `docs/UI_CHANGELOG.md` entry appended
- [ ] Build passes: `cd frontend && npm run build`
- [ ] Type check passes: `cd frontend && npx tsc --noEmit`

## 9. Escalation

When the protocol breaks down (e.g., backend ships breaking change without
deprecation, frontend uses undocumented endpoint, both agents touch shared
spec without coordination):

1. **Halt the offending PR** if not yet merged.
2. **File in `docs/AGENT_BACKLOG.md`** under `[PROTOCOL]` describing the violation.
3. **User mediates** — the human owner reads the backlog item and arbitrates.
4. **Update this document** if the protocol needs to evolve (PR labeled
   `area:protocol`, both agents must approve).
