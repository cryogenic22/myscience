MARKET ZERO · ENGAGEMENT WORKFLOW · AGENTIC UX DESIGN · 1 JUN 2026

An engagement is an agent crew you supervise

Research + design for the 7-stage engagement experience. The question isn't "how do we wire these stages" — it's "what is the right division of labour between autonomous agents and the human expert, and how does the interface make that division legible, trustworthy, and beautiful." This doc sets the operating model and the per-stage design; the wiring follows it.

1 · The operating model — agents do the work, you make the calls

We already run three agent loops (the Helix v8 model). The UX should make them visible and supervisable, not hidden:

  • Data Automaton acquire → normalise → extract → reconcile → publish facts (with provenance).
  • Intelligence Agent scope → template → assemble → verify → compose the dossier + scenarios.
  • Helix sense → decide → act → learn (re-calibrate from outcomes).

The human is not a data-entry clerk — they are the supervisor and decision-maker. The core interaction loop at every stage is the same:

▣ AGENT does the heavy lifting autonomously and shows its work, confidence, and sources │ ◇ HUMAN reviews at a checkpoint → approve · steer (add context / correct) · send back │ ▣ AGENT incorporates the steer, advances the stage, and logs what changed
The trust contract — three things every agent output must show.

This is what separates a credible agentic system from a chatbot, and it's the backbone of the aesthetic:

  • Provenance — every claim links to its source (we ship sourceUrl on facts now). Nothing is asserted without a trail.
  • Confidence — every output carries a tier (reference / corporate / signal / inferred) and a readiness score. The human sees how much to trust it.
  • Gaps — the agent names what it couldn't establish (we ship actionable gaps now). Honesty about the unknown is a feature, not a flaw.

HITL isn't binary. Each stage sits somewhere on a spectrum, and the UI should reflect it:

4 · Cross-cutting UX patterns (the parts that make it feel agentic)

The agent activity rail

A persistent right-rail (or header strip) shows what the agents are doing right now for this engagement — the live sense → decide → act → learn pulse. Not a spinner; a legible feed of "Data Automaton published 14 facts · Intelligence Agent verified domain 4 · 6 gaps surfaced." It makes the autonomy felt.

Readiness as the spine of navigation

Each stage in the stepper carries a readiness ring (0–100%), not just done/not-done. The engagement-level readiness (the benchmark's "87%") is the headline. Low readiness on a critical stage is the agent telling you where your attention is worth most.

Provenance drill-through everywhere

Any fact, number, or claim is clickable → opens the source (we ship sourceUrl). This is the anti-hallucination promise made visible; it's what lets an expert trust an agent-authored dossier.

Steering, not forms

The human adds context by talking to the stage ("weight the payer lens higher", "this competitor matters more than its edge count suggests") — an inline steer box per stage, not a 20-field form. The agent re-runs with the steer and shows the diff.

5 · Next-gen aesthetic direction

The reference is the Helix v8 demo: calm, dark, provenance-forward, editorial. Concretely:

  • Calm dark canvas, editorial type. Serif display (Fraunces / Source Serif) for headings + insight prose; a clean sans for body; mono for facts, IDs, provenance. Intelligence should read like a well-set briefing, not a dashboard.
  • Confidence-tiered color, not decoration. Color carries meaning: a fact-class glyph (◇ reference · ◆ corporate · ◈ signal · ✦ inferred), readiness greens/ambers, the ZS orange reserved for the decision / the recommended move. Restraint is the aesthetic.
  • Agent presence, quietly. A subtle "agent is working" shimmer + the activity rail — the system feels alive and autonomous without being noisy.
  • Progressive disclosure. Each stage opens with the headline + readiness; detail (facts, provenance, gaps) expands on intent. The expert isn't drowned; they drill where they care.
  • Motion with meaning. When the agent advances a stage or re-calibrates a probability, a small, purposeful transition shows the change (prior → current). Never gratuitous.

6 · Implementation sequence (build to the design)

Wiring follows the design, highest-readiness-to-ship first. Each is a loop (real-DB gated):

  • Now — scenarios stage. Backend ready (G1), ScenariosPage fully built (just orphaned). Add scenariosApi + a ScenariosContainer (mirror DossierContainer: assemble-on-demand → render) + wire into the stepper. The reference implementation of the agent→HITL pattern. Seed a demo engagement so it's live.
  • Next — gaps + synthesis. Gaps backend exists (/dossier/gaps); wire GapsContainer. Synthesis = the H16 narrative engine surfaced as the cross-domain insight (propose-confirm).
  • Then — brief + sources. Brief = BCB propose-confirm (backend exists). Sources = coverage view over the 8 classes (read-only first).
  • Then — workshop. Bring the war-game cockpit into the stepper as the co-pilot stage (it exists as a separate tab today).
  • Cross-cutting — the agent activity rail + readiness rings + steer box as shared components, applied across stages.
Honest constraint.

The experience is only as good as the data underneath. Two known gaps gate the demo quality: the orphaned high-value events (approvals/trials/deals not yet entity-resolved → PB-H19) and the junk competitor rows (need the A6 destructive cleanup). A clean branded asset will demo far better than metformin. The agentic UX makes the data's honesty visible — which is the point — but landing the strategic facts (PB-H19) is what makes a stage like synthesis sing.
