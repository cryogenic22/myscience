DataHub Pillars Walkthrough Architecture AI flows Reuse vs new Roadmap
Vision & design · 2026-06-13

An AI-led DataHub for connection, curation & intelligence — in one catalog.

Onboard any source — API, RSS, CSV, a website, Snowflake/Databricks — see it all in one place, FAIR-profile and curate it, and let agents create connectors and keep the data products enriching themselves on a schedule. Built mostly from what the system already has; portable to other systems by design.

The one line — never make onboarding a new data source an engineering project again: make it a product. Connect → catalog → curate → autonomously enrich, with provenance and governance as the floor.
🔌 Connect anything 🗂️ One catalog 🧪 FAIR profiles 🤖 AI-built connectors ♻️ Autonomous enrichment 🛡️ Governed by default 📦 Portable module
The product

Five pillars — and most of the substrate already exists

This isn't greenfield. ~80% of the code and ~95% of the architecture is reuse/extend; the differentiated build is generic connectors, an AI onboarding layer, and the catalog UX.

01

Catalog

See, search & browse every source, dataset and entity — connector type, status, data type, FAIR profile. CRUD as a curator.

~70% built
02

Connect

Onboard any source kind through a guided wizard — REST, RSS, CSV/file, website, warehouse.

framework ~60%
03

Curate

Auto-curate, clean, dedupe + human CRUD. See what the steward did and the FAIR delta.

~80% built
04

Enrich

"Gather X for every Y and integrate it." Set a schedule. Keep the data products richer each cycle.

loop ~50%
05

Govern

Provenance, lineage, lifecycle, license/trust, conservation gates — fail closed, never silent.

~85% built

The two flagship AI flows

From a link, and from a sentence

Flow A — Onboard from a link

"Connect this URL / this CSV / this warehouse table."

1Sample — SiteCrawler/fetcher pulls a sample (HTML/PDF/CSV head); robots + rate aware.
2Infer — SchemaInference proposes connector type, RecordType, field→column map, extraction schema, trust tier + cadence, with per-field confidence.
3Synthesize — ConnectorSynthesis emits a declarative config (preferred) and dry-runs in a sandbox — no writes.
4Preview — shows the records it would land + a draft FAIR profile for review.
5Publish — registers the source, writes the schedule, first real run lands rows; catalog goes live.

Flow B — Enrich everything, on a schedule

"Browse the company names, gather their financials from filings, auto-curate & integrate — and keep doing it."

1Compile — co-pilot turns the sentence into a job: target set = SELECT companies, per-target plan = find filings → extract → resolve → emit facts.
2Run — the AutonomousResearchAgent loop, generalized to external fetch: per target, commit-or-revert on FAIR delta + false-link detection.
3Evidence — every gathered fact carries source_doc_id + evidence; low-confidence routes to a human-review queue.
4Schedule — ScheduleSynthesizer sets a recurring cadence; DataSteward keeps cleaning/deduping.
5Learn — learning_service (EWMA) tracks per-connector accuracy and auto-flags drift.

How we build it

In loops — each one shippable

Every loop ships RED→GREEN with a real prod probe, a green Lane-1 gate, no conservation regression, and an independent review — the way this codebase already works.

L1 Catalog Home + source dossier over existing APIs L2 Connector-type taxonomy + onboarding lifecycle + dynamic source registration

L3 CsvConnector + RestApiConnector L4 Rss + WebScrape + Warehouse connectors L5 Connect wizard + ScheduleSynthesizer

Guardrails & success

What keeps AI-led ingestion safe

  • Codegen safety — prefer declarative connector configs over generated code; if code, sandbox + static-check + human-approve before it touches the scheduled path.
  • Crawl etiquette / legal — robots.txt, rate limits, ToS respected; licensed/paywalled sources stay planned contracts, never scraped.
  • No hallucinated schema / false links — confidence floors, a human-review queue, and the research agent's false-link detection + FAIR-delta commit-or-revert.
  • Provenance always — every autonomously gathered fact carries source_doc_id + evidence; conservation gates fail closed otherwise.
  • No vacuous catalog — a source that lands 0 rows shows RED, not "connected"; "the job ran" ≠ "the product is healthy."
  • Success metrics — time-to-onboard (engineer-days → curator-minutes); % onboarded via AI; facts & FAIR-delta per enrichment cycle; sources with contract+FAIR+green; # domains served from a swapped pack.
