Governed Semantic Resolution

A domain-pack architecture for identity-level-aware, explainable, steward-governed resolution — reconciling the red-team challenge, the data-intelligence strategy, Domain Forge, and the SME's pack specs.

Supersedes the standalone Phase-1 note · branch claude/data/semantic-resolution

The thesis, restated with the SME. A "match" is not one thing. The system must never be allowed to mark something resolved without stating at what level and what it is still uncertain about. The SME's verdict is decisive: this belongs in a versioned, SME-authorable domain pack, not hidden in resolver code — because the pack controls not just what matches, but what may become a Fact, what must become a Gap, and what must be routed to a steward. The engine is generic; the pharma judgement is data.

3 · The engine (generic runtime, pack-configured)

parse → typed attrs→ candidates / level→ compare (4-valued)→ score (explainable)→ flag→ route auto/review/escalate→ persist→ learn

Preserve, don't strip

drug_mention_parser turns text into typed Quantity (strength·concentration·volume· activity), formulation, route (with inferred flag), combo components, salt/release, regimen & context flags — and always keeps original_text. The legacy normalizer did the opposite (stripped them).

Four-valued comparison

Each attribute is confirmed inferred missing contradictory / irrelevant. Missing ≠ contradictory — a strengthless candidate yields a partial ingredient-level match, not a false one.

Identity levels (canonical)

ingredient_level → product_level → configuration_level → market_authorisation_level, plus regimen_level for treatment instructions that are not identity. Level is capped by the attributes actually confirmed; a contradiction caps it at ingredient.

Explainable confidence + routing

A 14-dimension breakdown (weights from the pack) minus ambiguity/risk penalties. Critical flags (mono-combo, dose-volume, form/route, contradiction) force escalate; soft flags → review; only a clean high-margin match → auto.

Everything pharma-specific is in the pack. Example — the same engine, two use-cases, by config alone:

policy:                          # commercial use-case          | epidemiology use-case
  collapse_salt: false           #   keep salt forms distinct    |   true (roll up to ingredient)
  distinguish_market: true       #   US ≠ EU product             |   false
  combo_only_components:         #   sacubitril resolves to combo without a flag…
    [sacubitril, lcz696]         #   …metformin does NOT (it is normally standalone) → flagged

4 · Bringing sources together (integration + ontology)

Integration is attribute union with per-source provenance against a shared identity graph, not "pick the best string". Different sources know a drug at different levels; the ontology supplies the join keys.

SourceKnows at levelCross-walk key
ClinicalTrials.govingredient / combinationNCT, intervention name
FDA SPL labelsconfiguration / brand / market(US)RxCUI, set_id
FAERSingredient (messy)generic name → UNII
ChEMBLsubstance / saltUNII, molecule ChEMBL id
NADAC / pricingconfiguration / packNDC, GTIN
RxNorm / ATC (ontology)the spine — all levelsIN·MIN·SCD·SBD term types
  • Resolve to the right node at the most specific level the mention's attributes confirm.
  • Union, don't overwrite — each (entity, attribute) keeps its asserting sources + reliability; agreement raises confidence, a gap-fill enriches.
  • Contradiction → flag, never silent-merge (SPL "subcutaneous" vs another "oral" → FORM_ROUTE_CONFLICT to a steward). This is the hook for the contradiction engine (Loop 8).
  • Use-case decides roll-up via the policy — the modular contract.

5 · Confidence, stewardship & the curator UI (from YAML_pack1)

The SME's confidence/stewardship pack is authoritative for bands, queues and the curator surface — it converges with the data-trust observability loop (Loop 11):

Confidence bands

deterministic ≥0.97 (exact id) → auto · strong ≥0.90 → auto-with-audit · usable 0.75–0.90 → review if client-facing · ambiguous 0.50–0.75 → human review · weak <0.50 → do-not-resolve. Never auto over a critical flag.

Stewardship queues

Routed by flag: entity-resolution (mono-combo, configuration, acronym), fact-quality (contradiction, missing attr), access-pricing (price-without-pack/market), scenario-impact (probability Δ>5pp, recommendation). Owners are SME roles.

Curator UI contract

Extraction context · proposed resolution + level · attribute-comparison table · confidence breakdown · alternatives (why-not) · lineage (evidence/extraction/resolver/model/pack ids) · downstream impact · one-click approve/reject/split/merge/remap/create-canonical/add-alias/open-gap.

Learning loop (Domain Forge)

Every steward correction creates ≥1 of: alias / exclusion / ontology edge / source-contract update / threshold change / gold eval case / regression test. Never a silent pack overwrite; promotion gated on eval-pass + owner approval + rollback.

6 · Build sequencing (the SME's order)

Phase 1 — Engine + semantic-resolution pack shipped (this branch)

  • drug_mention_parser.py (typed, attribute-preserving) + semantic_resolution.py (levels, 4-valued comparison, 14-dim confidence, canonical flags, auto/review/escalate).
  • packs/pharma_semantic_resolution.yaml + packs/eval_semantic_resolution.yaml + packs/loader.py — the engine is pack-driven; behaviour is data.
  • 66 tests incl. a data-driven runner over the YAML golden set (all red-team categories).

Phase 2 — Foundational contract packs + wiring next loops

  • pharma_source_contracts (Loop 10) → trust tier drives source_reliability.
  • pharma_fact_signal_gap_contracts (Loops 5·6·9) → the Fact carries resolution_level, resolver_audit_id, contradiction index; Gap + CalibrationEvent become first-class.
  • pharma_confidence_stewardship_eval (Loop 11) → bands, queues, curator UI substrate.
  • Migration: persist ResolutionDecision; wire the parser into entity_resolver.py so ingest attaches level + attributes + flags and routes to the queues. RxNorm/ATC/UNII cross-walk ingest.

Phase 3 — Therapy playbooks + curator cockpit later

  • obesity_metabolic_playbooks (GLP-1/GIP/amylin, weight-loss/HbA1c/MACE endpoints, titration, access).
  • Curator UI (frontend lane) on the contract above; Domain Forge round ④ feeds pack edits + gold labels.
