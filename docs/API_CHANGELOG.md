## 2026-05-09 — SPEC_023 Decision Briefs

### Added
- `POST /decision-briefs` (uploader+) — create draft brief. Body:
  `{ question, trigger_kind, trigger_signal_ids?, trigger_metadata?, stakeholders?,
   time_horizon_days?, evidence_refs?, constraints?, success_criteria?,
   confidence_to_proceed?, war_room_id? }`. Returns 201 with full brief object
   (including initial state-log entry). Trigger kinds: `manual|threshold|cluster|calendar`.
- `GET /decision-briefs` (viewer+) — list with filters: `state`, `owner_user_id`,
  `trigger_kind`, `include_archived`, `limit` (1-500), `offset`. Returns
  `{ briefs[], limit, offset, count }`.
- `GET /decision-briefs/{brief_id}` (viewer+) — full brief with options +
  state log. Pass `?include_archived=true` to fetch archived briefs.
- `PATCH /decision-briefs/{brief_id}` (uploader+) — edit fields. Only
  legal in `draft` or `human_review` states; returns 409 otherwise.
- `DELETE /decision-briefs/{brief_id}` (uploader+) — archive (sets
  `archived_at`). Only legal for non-committed states; 409 otherwise.
- `POST /decision-briefs/{brief_id}/options` (uploader+) — append option.
  Auto-assigns sequential `ordinal`. Body: `{ label, description?,
  predicted_outcome?, cost_estimate?, risk_notes? }`.
- `DELETE /decision-briefs/{brief_id}/options/{option_id}` (uploader+) —
  remove option. 204 No Content.
- `POST /decision-briefs/{brief_id}/transitions` (uploader+) — transition
  state machine. Body: `{ to_state, reason? }`. Returns 409 on illegal
  transition or insufficient options for `simulation_pending` (requires ≥2).

### Changed
- **Bug fix in `api/exception_handlers.py`**: validation_exception_handler
  now sanitizes pydantic v2 error dicts before JSON serialization. Pydantic
  v2 attaches the original Python exception (e.g. `ValueError`) to
  `ctx.error`, which previously caused the handler to raise `TypeError`
  when a route used a `field_validator`. **No breaking change** for
  existing clients — error envelope shape is identical, just no longer
  500s on `ValueError`-based validators.

### State machine (Decision Briefs)
- 8 states: `draft`, `human_review`, `simulation_pending`, `simulation_complete`,
  `decision_pending`, `committed`, `in_review`, `closed`
- Legal transitions enforced server-side; full table in `specs/SPEC_023_decision_briefs.md`
- Every transition writes to `decision_brief_state_log` (immutable audit trail)
- `simulation_pending` requires ≥2 options (service-level guard, returns 409)
- `committed` requires `decision_id` to be attached (service-level guard, returns 400)

### Migration notes for frontend
- New surface for Antigravity: **Decision Workspace** (`[FRONTEND] Decision
  Workspace` backlog item) is now unblocked. Spec §9.1.2 describes the
  5-panel layout (Brief, Evidence, Simulation, Recommendation, Reasoning).
- For the Reasoning Trace drawer: read `state_log[]` from `GET
  /decision-briefs/{id}` — it's a chronological list of all state
  transitions with `from_state`, `to_state`, `actor_user_id`, `reason`,
  `transitioned_at`.
- For the option-ranking UI in the Recommendation panel: options come
  back ordered by `ordinal ASC`. Each option carries `predicted_outcome`,
  `cost_estimate`, `risk_notes` for tooltip/expansion.
- Migration 052 must run on prod before this surface goes live.
  `POST /debug/migrate` triggers it.

## 2026-05-09 — SPEC_024 Evidence Ledger

### Added
- `POST /claims` (uploader+) — create or upsert claim. Dedup on
  `(claim_text_hash, entity_type, entity_id)` — same claim about same
  entity returns existing `claim_id`. Body: `{ claim_text, claim_type?,
  entity_type?, entity_id?, confidence? }`. Claim types: `regulatory |
  clinical | commercial | pricing | safety | pipeline | other`. Entity
  types: `drug | company | trial | indication | mechanism | therapeutic_area
  | event | patent | literature`.
- `GET /claims` (viewer+) — list claims with filters: `entity_type`,
  `entity_id`, `claim_type`, `text_query`, `limit` (1-500), `offset`.
- `GET /claims/{claim_id}` (viewer+) — full claim with all backing
  evidence (ordered by confidence DESC). `?include_evidence=false` to skip.
- `POST /claims/{claim_id}/evidence` (uploader+) — append evidence
  to a claim. Body: `{ source_id, extracted_text, retrieved_at?,
  source_url?, extraction_method?, confidence?, relation? }`. Dedup on
  `(source_content_hash, source_id, retrieved_at::date)` — replaying
  the same evidence on the same day returns the existing record.
  `relation` ∈ `supports | contradicts | qualifies` (default `supports`).
- `GET /evidence/{evidence_id}` (viewer+) — get one evidence record.
- `POST /briefs/{brief_id}/evidence-snapshot` (uploader+) — freeze
  the (claim → evidence_ids) mapping for the given claim_ids into a
  content-addressed immutable snapshot. **Idempotent** — re-snapshotting
  the same set returns the same `snapshot_hash`.
- `GET /evidence-snapshots/{snapshot_hash}` (viewer+) — reconstruct
  a snapshot. `snapshot_hash` is hex-encoded SHA-256.

### Hashing (deterministic, exposed as service helpers)
- `claim_text_hash`: `sha256(claim_text.strip().encode("utf-8"))`
- `source_content_hash`: `sha256(extracted_text.encode("utf-8"))` (no trim)
- `snapshot_hash`: `sha256(canonical_json(body).encode("utf-8"))` where
  body is `{claims: [{claim_id, evidence_ids[]}], brief_id?, decision_id?}`
  with claims sorted by `claim_id` and evidence_ids sorted lexically.
  `snapshot_at` is NOT in the hashed body (idempotency).

### Append-only enforcement
- DB triggers reject UPDATE on `evidence_records` (except one-time
  `archived_snapshot_ref` fill) and reject DELETE entirely. ERRCODE
  `42501` (insufficient_privilege).

### Migration notes for frontend
- New surface for Antigravity: **Evidence Affordance** primitive. Wire
  `<EvidenceAffordance claimId={...} />` to `GET /claims/{claim_id}` —
  payload includes `evidence[]` with source, retrieved_at, exact passage,
  confidence per evidence record.
- For the Decision Workspace Evidence Panel: filter brief.evidence_refs
  for `type=='claim'` items, fetch each claim with evidence, render with
  confidence indicators.
- Migration 053 must run on prod before this surface goes live.

## 2026-05-09 — SPEC_026 LLM Gateway + Prompt Registry

### Added
- `POST /llm-gateway/prompts` (uploader+) — register or upsert prompt.
  Body: `{ name, content, purpose?, model_pref?, max_tokens? }`. Idempotent
  on `(name, content)` — same content = same prompt_id. Different content
  for an existing name → version+1.
- `GET /llm-gateway/prompts` (viewer+) — list with optional `name` filter.
- `GET /llm-gateway/prompts/{prompt_id}` (viewer+) — get one prompt.
  Response includes `variables[]` (auto-extracted from `{{var}}` template
  references in content).
- `POST /llm-gateway/invoke` (uploader+) — invoke a registered prompt.
  Body: `{ prompt: name|prompt_id, variables, user_message?, version?,
  model_pref?, max_tokens?, pii_policy? }`. PII policies: `redact` (default,
  PII replaced with `[KIND]`), `reject` (409 if PII detected), `allow`.
  Returns `{ response, prompt_id, model_used, latency_ms, prompt_tokens,
  completion_tokens, cost_estimate_usd, pii_redactions[], succeeded, error }`.
- `POST /llm-gateway/scan-pii` (uploader+) — diagnostic; scan text for
  PII without invoking the LLM. Returns `{ matches[], redacted, match_count }`.
- `GET /llm-gateway/cost-summary` (viewer+) — cost aggregation. Query
  params: `since` (date), `until` (date, default today), `group_by`
  ∈ `caller | model | day | user | prompt_id` (default `caller`).
  Default range: last 7 days. Returns `{ since, until, group_by,
  total_usd, total_calls, buckets[] }`.

### Changed
- **`llm_call_log` augmented** (additive, back-compat): added nullable
  `prompt_id UUID` column referencing `prompt_registry(prompt_id)`. NULL
  for legacy callers; populated when invocation goes through the Gateway.
- New indexes on `llm_call_log` for `(caller, day)` and `(user_id, day)`
  to support cost-summary queries efficiently.

### PII patterns (initial set)
- email — `[\w._%+-]+@[\w.-]+\.[A-Za-z]{2,}`
- ssn — `\b\d{3}-\d{2}-\d{4}\b`
- phone_us — US phone formats
- credit_card — 13-19 digit candidates, then Luhn-validated

### Template substitution
- Mustache-style `{{var}}` (with optional whitespace inside braces)
- **Single-pass substitution** — variable values are inserted verbatim and
  NEVER re-rendered (blocks template injection from caller-controlled values)
- Missing variables → 400 with the missing-key list

### Migration notes for frontend
- New surface (when ready): **Cost dashboard / observability admin** for
  Antigravity. Wire `GET /llm-gateway/cost-summary?group_by=caller` to a
  bar chart, `?group_by=day` to a sparkline. List prompts with `GET
  /llm-gateway/prompts` for an admin "registered prompts" view.
- Existing chat surfaces are unaffected — invoke via the Gateway is opt-in
  for callers that want versioned prompts; legacy `chat_with_telemetry`
  continues to work.
- Migration 054 must run on prod before this surface goes live.

## 2026-05-09 — SPEC_027 Source Registry + Quality Scoring

### Added
- `POST /sources` (uploader+) — register source. Idempotent on `source_id`.
  Body: `{ source_id, display_name, tier (1-4), kind (free|paid|internal),
  base_url?, description?, license_status?, license_renewal_at?,
  rate_limit_per_min?, usage_profile? }`.
- `GET /sources` (viewer+) — list with filters: `tier`, `kind`, `active`.
  Each source includes its `latest_quality` (the most recent quality row).
- `GET /sources/health-summary` (viewer+) — aggregate: `{ total_sources,
  active_count, scored_count, mean_overall_score, bottom_5[] }`.
- `GET /sources/{source_id}` (viewer+) — single source + latest quality.
- `PATCH /sources/{source_id}` (uploader+) — update display_name,
  description, active, license_status, license_renewal_at,
  rate_limit_per_min, usage_profile.
- `GET /sources/{source_id}/history` (viewer+) — quality time series
  (last N rows; default 100).
- `POST /sources/{source_id}/recompute` (uploader+) — compute fresh quality
  row, update `latest_quality_id` pointer.

### Quality scoring (5-dim)
- `coverage` (weight 0.25): tier-default until SPEC-028 wires real ground truth
- `latency` (0.20): p95 lag from `evidence_records.retrieved_at` over last 1000
- `predictive_accuracy` (0.30): default 0.5; SPEC-028 will populate
- `stability` (0.15): stub from `active` flag; future: connector lifecycle log
- `license_health` (0.10): `expired` → 0; `rate_limited` → 0.5; `active` →
  1.0 (linearly degraded in 30-day renewal window); `not_applicable` → 1.0
- `overall_score = Σ (weight × dimension)`, clamped [0, 1]

### Migration notes for frontend
- New surface: **Source Health admin** (spec §9.3). Wire
  `GET /sources/health-summary` for the headline strip,
  `GET /sources` for the per-source table (showing tier, license_status,
  overall_score, mean latency p95). Bottom-5 in summary highlights
  degraded sources.
- Migration 055 must run on prod before this surface goes live.

  evidence_snapshot, HMAC-sign canonical immutable fields, persist.
  Body: `{ claim_ids[] (≥1), brief_id?, force? }`. Returns
  `{ decision_id, snapshot_hash, signature, signing_algo, signed_at,

- HMAC-SHA256, signing_algo `hmac-sha256-v1`
- Server secret from env `MZ_DECISION_SIGNING_SECRET`; dev fallback emits WARN

## 2026-05-09 — SPEC_033 Counter-Recommendation Enforcement

### Added
- `POST /recommendations/synthesize` (uploader+) — synthesize a primary
  recommendation + at least one counter-rec from a list of options.
  Body: `{ brief_id?, options[{option_id, label, score, predicted_outcome?,
  risk_notes?, dimension_scores?}], method: 'score_based'|'dimension_split' }`.
  Returns `{ recommendation_id, primary, counter, dissent_score,
  synthesis_method }`. Persists to recommendation_synthesis_runs.
  **Hard rule**: ≥2 options required; <2 returns 422 with the violation
  reason (does not fake dissent).
- `GET /recommendations` (viewer+) — list with `brief_id` filter
- `GET /recommendations/{recommendation_id}` (viewer+) — fetch one

### Synthesis methods
- **score_based** (default): primary = highest score; counter = lowest
  scoring option (≠ primary). Dissent = `|p.score - c.score| / p.score`.
- **dimension_split**: primary = highest score; counter = option whose
  `dimension_scores` vector is most cosine-distant from primary's.
  Falls back to score_based if any option lacks dim_scores; method
  field records the actual method used.

### Counter-rec rule (enforced at three levels)
1. **Schema**: pydantic min_length=1 on options
2. **Service**: ≥2 options required; counter MUST differ from primary
3. **DB**: CHECK constraint `primary_option_id <> counter_option_id`
   on recommendation_synthesis_runs

When scores are equal, the service still picks a distinct counter and
reports `dissent_score = 0` honestly — never fakes disagreement.

### Migration 061 (additive)
- New `recommendation_synthesis_runs` table with audit fields.
  Conditional FK to decision_briefs (works regardless of deploy order).

### Migration notes for frontend
- **Frontend Claude task #7** (Dissent View Panel) is now unblocked.
  Wire `<DissentView primary={r.primary} counter={r.counter}
  dissentScore={r.dissent_score} />` to render the spec's "A unanimous
  AI is suspicious AI" surface.
- For the Decision Workspace Recommendation panel: call POST
  `/recommendations/synthesize` after the user finalizes options;
  display primary + counter side-by-side with the dissent score badge.
- Migration 061 must run on prod before this surface goes live.

## 2026-05-09 — SPEC_032 Learning Service

### Added
- `POST /learning/run` (uploader+) — execute the learning service. Body:
  `{ since?, alpha?, auto_register_unknown_sources? }`. Returns the
  persisted run row + summary including `attribution_methods` (which
  fallback path each decision used) and `skipped_reasons`.
- `GET /learning/runs` (viewer+) — list with optional `status` filter
- `GET /learning/runs/{run_id}` (viewer+) — single-run detail
- `GET /learning/source-attributions` (viewer+) — recent per-(decision,
  source) attribution events; filters: `source_id`, `since`, `limit`
- `GET /learning/prompt-flags` (viewer+) — recently-flagged prompts;
  optional `since_days`

### Math
- EWMA: `posterior = α * observation + (1 - α) * prior`; default `α = 0.10`
- NULL prior → seeds with raw calibration_score (no blend)
- Output clamped to [0, 1]

### Source attribution chain (tries in order)
1. **evidence_snapshot chain** (preferred): decision → snapshot → claims →
   evidence_records → source_id (full SPEC-024 chain)
2. **brief.evidence_refs fallback**: decision → brief → signal refs → source
3. **decision_source_signal last-resort**: decision.source_signal_id → source

The summary records which method was used per decision so attribution
quality is auditable.

### Prompt flagging
A prompt is flagged when in the last 30 days:
- ≥ 5 distinct users invoked it AND
- mean calibration of those users' decisions < 0.45
Reason: `low_calibration`. Flag persisted in `prompt_quality_flag`.

### Migration 060 (additive)
- `learning_service_runs` (append-only run log)
- `source_attribution_log` (audit per-(decision, source) attribution)
- `prompt_quality_flag` (rolling-window quality flags)

## 2026-05-09 — SPEC_031 Materiality Scoring

### Added
- `POST /materiality/score` (uploader+) — compute factor-attributed
  materiality. Body: `{ source_tier?, entity_criticality?, claim_type?,
  age_days?, signal_id? }`. Returns `{ materiality_score (0-100),
  materiality_factors: {factor: {input, value, weight, contribution}},
  score_method, weights_config_id }`. Each factor's `contribution` is
  `100 × weight × value`; the four contributions sum to score.
  When `signal_id` is provided, also persists score + factors to
  `signals.materiality_score` + `signals.materiality_factors` (best-effort).
- `GET /materiality/weights` (viewer+) — return active weight config.
  Frontend uses this to render the "what factors?" tooltip.
- `PUT /materiality/weights` (uploader+) — replace active weight config
  (admin tuning). Validates weights sum to 1.0, all factor values in [0, 1].

### Fallback behavior (graceful)
- Unknown `claim_type` → falls back to `'other'` (value 0.3); no exception
- Unknown `entity_criticality` → falls back to `'other'` (value 0.2)
- Missing `source_tier` → uses tier 3 default (0.4)
- Negative `age_days` → clamped to 0 (max recency)

### Migration 058 (additive)
- Adds `signals.materiality_factors JSONB` column (nullable)
- Creates `materiality_weight_config` (singleton via partial unique index)
- Seeds initial active config with documented defaults

### Migration notes for frontend

## 2026-05-09 — SPEC_029 Framing Triggers

### Added
- `POST /framing-triggers` (uploader+) — create trigger config. Body:
  `{ name, kind: 'threshold'|'cluster'|'calendar', config{...},
  assignee_user_id? }`. Each `kind` has its own whitelisted `config` shape;
  unknown keys rejected with 400 (R8 — config injection guard).
- `GET /framing-triggers` (viewer+) — list with `kind`, `is_active` filters
- `GET /framing-triggers/{trigger_id}` (viewer+)
- `PATCH /framing-triggers/{trigger_id}` (uploader+)
- `DELETE /framing-triggers/{trigger_id}` (uploader+) — 204
- `POST /framing-triggers/tick` (uploader+) — evaluate ALL active triggers
  now; returns per-trigger result. Failures isolated (one crash doesn't
  abort others).
- `POST /framing-triggers/{trigger_id}/evaluate` (uploader+) — evaluate one
- `GET /framing-triggers/{trigger_id}/fires` (viewer+) — recent fire log

### Trigger kinds
- **threshold**: fires on signal with `materiality_score >= min_score`
  (configurable, sane floor 50). Optional `claim_types`/`entity_types`
  whitelist. Each signal can fire at most once per trigger (dedup).
- **cluster**: fires when ≥`min_cluster_size` signals share `entity_field`
  within `rolling_window_days`. Optional `min_total_materiality` threshold.
  Per-(trigger, entity) dedup within window.
- **calendar**: fires when `NOW() >= next_fire_at`; advances `next_fire_at
  += interval_days` on success. Idempotent within interval.

### Auto-created brief shape
Each fire creates a `decision_briefs` row in `draft` state via SPEC-023:
- `trigger_kind` set to one of `threshold|cluster|calendar`
- `trigger_signal_ids[]` populated (empty for calendar)
- `trigger_metadata` carries trigger context (trigger_id, name, threshold,
  cluster size, etc.)
- `evidence_refs` includes `{type: 'signal', id}` per matched signal
- `owner_user_id` set from trigger.assignee_user_id (or null = unassigned)

### Migration 059 (additive)
- New tables `framing_triggers` (config) + `framing_trigger_fires` (event log)
- Conditional FK to `decision_briefs(brief_id)` (works regardless of deploy order)

### Migration notes for frontend
- New surface: trigger admin (lower priority — backend-driven for now).
  Eventually wire `GET /framing-triggers` to a tiny config UI.
- The Inbox surface (already built by Frontend Claude) automatically picks
  up auto-created briefs since they land in `draft` state visible to GETs.
- For the "why was this brief auto-framed?" tooltip on each brief card:
  read `brief.trigger_metadata` (already exposed in the brief payload).

- `GET /war-games` (viewer+) — list runs. Filters: `brief_id`, `status`,

- `GET /war-games/{run_id}` (viewer+) — run + adversary panel + summary
  (no actions).
- `GET /war-games/{run_id}/transcript` (viewer+) — full chronological
  action transcript ordered by round, then adversary.
- `POST /war-games/{run_id}/cancel` (uploader+) — cancel pending/running.

### Critical invariant: grounding rule
- Every action MUST cite an `evidence_record` (DB-enforced via NOT NULL FK
  on `war_game_actions.grounding_evidence_id`)
- Adversaries MUST carry ≥1 `grounding_evidence_ids` at start
  (schema-enforced via `min_length=1`)
- Per spec §6.3.2: "a war-game where the competitor agent does whatever
  the prompt suggests is theater, not analysis."

### Adversary kinds
- `competitor` — top-3 competitors with strategy + recent moves + financials
- `payer` — formulary economics, IRA pressure, recent decisions
- `regulator` — FDA/EMA posture, advisory committee patterns
- `kol` — clinical opinion-leader + patient advocacy reactions

### Action kinds
- `react`, `escalate`, `wait`, `concede`, `threat`, `counter`, `partner`

## 2026-05-09 — SPEC_025 Game-Theoretic Simulation

### Added
- `POST /game-theory/bayesian` (uploader+) — Bayesian war-game with type
  distributions. Body: `{ adversary: {name, kind, type_distribution,
  type_response_strengths}, options[], sample_count?, seed?, brief_id? }`.
  Returns posterior distributions (mean/std/p10/p50/p90) per output dim per option.
  Deterministic with `seed`; sampling tolerance otherwise.
- `POST /game-theory/stackelberg` (uploader+) — Leader-follower equilibrium
  on a discrete timing grid. Body: `{ timing_grid[], opponent_responses[],
  our_payoff[{timing, response, payoff}], opponent_payoff[...] }`. Returns
  `{optimal_timing, opponent_best_response, our_payoff, by_timing[]}`.
  Tie-break: lex-first response on opponent side (deterministic).
- `POST /game-theory/pomdp` (uploader+) — Value-of-information for
  decide-now vs wait. Body: `{ options{id: utility}, upcoming_signals[
  {name, arrival_days, expected_info_value, posterior_shifts}],
  discount_rate_per_day? }`. Returns `{recommendation: 'wait'|'decide',
  wait_for_signal, best_wait_option, delta_vs_decide_now, per_signal[]}`.
- `GET /game-theory/runs` (viewer+) — list with filters `brief_id`, `kind`.
- `GET /game-theory/runs/{run_id}` (viewer+) — get one run with inputs +
  outputs (full audit trail).

### Migration 057 (additive)
- New table `game_theory_runs` (append-only): brief_id, kind, inputs_jsonb,
  outputs_jsonb, compute_ms, started_by_user_id, created_at.

### Migration notes for frontend
- New surface: **Decision Workspace Simulation panel** (spec §9.1.2 center)
  consumes `GET /game-theory/runs?brief_id={id}` to show all simulations
  attached to a brief, and renders Bayesian distributions / Stackelberg
  by_timing tables / POMDP wait-vs-decide cards.
- All three POST endpoints are synchronous; compute_ms is captured for
  observability.
- Migration 057 must run on prod before this surface goes live.

### Discipline note (per spec §6.3.2 + game-theory addendum)
- These services compute equilibria; the human supplies priors. A
  Stackelberg model with hand-waved payoffs is worse than a well-reasoned
  narrative war-game. The frontend should require the user to source the
  payoff matrices (manually or via Decision Brief evidence_refs) rather
  than auto-populate.
