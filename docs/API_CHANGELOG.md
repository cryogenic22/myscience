at the start of every session.**

`### Deprecated`, `### Removed`, `### Migration notes for frontend`. Omit
empty sections.

## 2026-05-09 — SPEC_023 Decision Briefs

### Added
- `POST /decision-briefs` (uploader+) — create draft brief. Body:
  `{ question, trigger_kind, trigger_signal_ids?, trigger_metadata?, stakeholders?,
   time_horizon_days?, evidence_refs?, constraints?, success_criteria?,
   confidence_to_proceed?, war_room_id? }`. Returns 201 with full brief object
   (including initial state-log entry). Trigger kinds: `manual|threshold|cluster|calendar`.
- `GET /decision-briefs` (viewer+) — list with filters: `state`, `owner_user_id`,
  `trigger_kind`, `include_archived`, `limit` (1-500), `offset`. Returns
  `{ briefs[], limit, offset, count }`.
- `GET /decision-briefs/{brief_id}` (viewer+) — full brief with options +
  state log. Pass `?include_archived=true` to fetch archived briefs.
- `PATCH /decision-briefs/{brief_id}` (uploader+) — edit fields. Only
  legal in `draft` or `human_review` states; returns 409 otherwise.
- `DELETE /decision-briefs/{brief_id}` (uploader+) — archive (sets
  `archived_at`). Only legal for non-committed states; 409 otherwise.
- `POST /decision-briefs/{brief_id}/options` (uploader+) — append option.
  Auto-assigns sequential `ordinal`. Body: `{ label, description?,
  predicted_outcome?, cost_estimate?, risk_notes? }`.
- `DELETE /decision-briefs/{brief_id}/options/{option_id}` (uploader+) —
  remove option. 204 No Content.
- `POST /decision-briefs/{brief_id}/transitions` (uploader+) — transition
  state machine. Body: `{ to_state, reason? }`. Returns 409 on illegal
  transition or insufficient options for `simulation_pending` (requires ≥2).

### Changed
- **Bug fix in `api/exception_handlers.py`**: validation_exception_handler
  now sanitizes pydantic v2 error dicts before JSON serialization. Pydantic
  v2 attaches the original Python exception (e.g. `ValueError`) to
  `ctx.error`, which previously caused the handler to raise `TypeError`
  when a route used a `field_validator`. **No breaking change** for
  existing clients — error envelope shape is identical, just no longer
  500s on `ValueError`-based validators.

### State machine (Decision Briefs)
- 8 states: `draft`, `human_review`, `simulation_pending`, `simulation_complete`,
  `decision_pending`, `committed`, `in_review`, `closed`
- Legal transitions enforced server-side; full table in `specs/SPEC_023_decision_briefs.md`
- Every transition writes to `decision_brief_state_log` (immutable audit trail)
- `simulation_pending` requires ≥2 options (service-level guard, returns 409)
- `committed` requires `decision_id` to be attached (service-level guard, returns 400)

### Migration notes for frontend
- New surface for Antigravity: **Decision Workspace** (`[FRONTEND] Decision
  Workspace` backlog item) is now unblocked. Spec §9.1.2 describes the
  5-panel layout (Brief, Evidence, Simulation, Recommendation, Reasoning).
- For the Reasoning Trace drawer: read `state_log[]` from `GET
  /decision-briefs/{id}` — it's a chronological list of all state
  transitions with `from_state`, `to_state`, `actor_user_id`, `reason`,
  `transitioned_at`.
- For the option-ranking UI in the Recommendation panel: options come
  back ordered by `ordinal ASC`. Each option carries `predicted_outcome`,
  `cost_estimate`, `risk_notes` for tooltip/expansion.
- Migration 052 must run on prod before this surface goes live.
  `POST /debug/migrate` triggers it.

## 2026-05-09 — SPEC_024 Evidence Ledger

### Added
- `POST /claims` (uploader+) — create or upsert claim. Dedup on
  `(claim_text_hash, entity_type, entity_id)` — same claim about same
  entity returns existing `claim_id`. Body: `{ claim_text, claim_type?,
  entity_type?, entity_id?, confidence? }`. Claim types: `regulatory |
  clinical | commercial | pricing | safety | pipeline | other`. Entity
  types: `drug | company | trial | indication | mechanism | therapeutic_area
  | event | patent | literature`.
- `GET /claims` (viewer+) — list claims with filters: `entity_type`,
  `entity_id`, `claim_type`, `text_query`, `limit` (1-500), `offset`.
- `GET /claims/{claim_id}` (viewer+) — full claim with all backing
  evidence (ordered by confidence DESC). `?include_evidence=false` to skip.
- `POST /claims/{claim_id}/evidence` (uploader+) — append evidence
  to a claim. Body: `{ source_id, extracted_text, retrieved_at?,
  source_url?, extraction_method?, confidence?, relation? }`. Dedup on
  `(source_content_hash, source_id, retrieved_at::date)` — replaying
  the same evidence on the same day returns the existing record.
  `relation` ∈ `supports | contradicts | qualifies` (default `supports`).
- `GET /evidence/{evidence_id}` (viewer+) — get one evidence record.
- `POST /briefs/{brief_id}/evidence-snapshot` (uploader+) — freeze
  the (claim → evidence_ids) mapping for the given claim_ids into a
  content-addressed immutable snapshot. **Idempotent** — re-snapshotting
  the same set returns the same `snapshot_hash`.
- `GET /evidence-snapshots/{snapshot_hash}` (viewer+) — reconstruct
  a snapshot. `snapshot_hash` is hex-encoded SHA-256.

### Hashing (deterministic, exposed as service helpers)
- `claim_text_hash`: `sha256(claim_text.strip().encode("utf-8"))`
- `source_content_hash`: `sha256(extracted_text.encode("utf-8"))` (no trim)
- `snapshot_hash`: `sha256(canonical_json(body).encode("utf-8"))` where
  body is `{claims: [{claim_id, evidence_ids[]}], brief_id?, decision_id?}`
  with claims sorted by `claim_id` and evidence_ids sorted lexically.
  `snapshot_at` is NOT in the hashed body (idempotency).

### Append-only enforcement
- DB triggers reject UPDATE on `evidence_records` (except one-time
  `archived_snapshot_ref` fill) and reject DELETE entirely. ERRCODE
  `42501` (insufficient_privilege).

### Migration notes for frontend
- New surface for Antigravity: **Evidence Affordance** primitive. Wire
  `<EvidenceAffordance claimId={...} />` to `GET /claims/{claim_id}` —
  payload includes `evidence[]` with source, retrieved_at, exact passage,
  confidence per evidence record.
- For the Decision Workspace Evidence Panel: filter brief.evidence_refs
  for `type=='claim'` items, fetch each claim with evidence, render with
  confidence indicators.
- Migration 053 must run on prod before this surface goes live.
