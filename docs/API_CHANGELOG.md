## 2026-05-09 — SPEC_023 Decision Briefs

### Added
- `POST /decision-briefs` (uploader+) — create draft brief. Body:
  `{ question, trigger_kind, trigger_signal_ids?, trigger_metadata?, stakeholders?,
   time_horizon_days?, evidence_refs?, constraints?, success_criteria?,
   confidence_to_proceed?, war_room_id? }`. Returns 201 with full brief object
   (including initial state-log entry). Trigger kinds: `manual|threshold|cluster|calendar`.
- `GET /decision-briefs` (viewer+) — list with filters: `state`, `owner_user_id`,
  `trigger_kind`, `include_archived`, `limit` (1-500), `offset`. Returns
  `{ briefs[], limit, offset, count }`.
- `GET /decision-briefs/{brief_id}` (viewer+) — full brief with options +
  state log. Pass `?include_archived=true` to fetch archived briefs.
- `PATCH /decision-briefs/{brief_id}` (uploader+) — edit fields. Only
  legal in `draft` or `human_review` states; returns 409 otherwise.
- `DELETE /decision-briefs/{brief_id}` (uploader+) — archive (sets
  `archived_at`). Only legal for non-committed states; 409 otherwise.
- `POST /decision-briefs/{brief_id}/options` (uploader+) — append option.
  Auto-assigns sequential `ordinal`. Body: `{ label, description?,
  predicted_outcome?, cost_estimate?, risk_notes? }`.
- `DELETE /decision-briefs/{brief_id}/options/{option_id}` (uploader+) —
  remove option. 204 No Content.
- `POST /decision-briefs/{brief_id}/transitions` (uploader+) — transition
  state machine. Body: `{ to_state, reason? }`. Returns 409 on illegal
  transition or insufficient options for `simulation_pending` (requires ≥2).

### Changed
- **Bug fix in `api/exception_handlers.py`**: validation_exception_handler
  now sanitizes pydantic v2 error dicts before JSON serialization. Pydantic
  v2 attaches the original Python exception (e.g. `ValueError`) to
  `ctx.error`, which previously caused the handler to raise `TypeError`
  when a route used a `field_validator`. **No breaking change** for
  existing clients — error envelope shape is identical, just no longer
  500s on `ValueError`-based validators.

### State machine (Decision Briefs)
- 8 states: `draft`, `human_review`, `simulation_pending`, `simulation_complete`,
  `decision_pending`, `committed`, `in_review`, `closed`
- Legal transitions enforced server-side; full table in `specs/SPEC_023_decision_briefs.md`
- Every transition writes to `decision_brief_state_log` (immutable audit trail)
- `simulation_pending` requires ≥2 options (service-level guard, returns 409)
- `committed` requires `decision_id` to be attached (service-level guard, returns 400)

### Migration notes for frontend
- New surface for Antigravity: **Decision Workspace** (`[FRONTEND] Decision
  Workspace` backlog item) is now unblocked. Spec §9.1.2 describes the
  5-panel layout (Brief, Evidence, Simulation, Recommendation, Reasoning).
- For the Reasoning Trace drawer: read `state_log[]` from `GET
  /decision-briefs/{id}` — it's a chronological list of all state
  transitions with `from_state`, `to_state`, `actor_user_id`, `reason`,
  `transitioned_at`.
- For the option-ranking UI in the Recommendation panel: options come
  back ordered by `ordinal ASC`. Each option carries `predicted_outcome`,
  `cost_estimate`, `risk_notes` for tooltip/expansion.
- Migration 052 must run on prod before this surface goes live.
  `POST /debug/migrate` triggers it.

## 2026-05-09 — SPEC_026 LLM Gateway + Prompt Registry

### Added
- `POST /llm-gateway/prompts` (uploader+) — register or upsert prompt.
  Body: `{ name, content, purpose?, model_pref?, max_tokens? }`. Idempotent
  on `(name, content)` — same content = same prompt_id. Different content
  for an existing name → version+1.
- `GET /llm-gateway/prompts` (viewer+) — list with optional `name` filter.
- `GET /llm-gateway/prompts/{prompt_id}` (viewer+) — get one prompt.
  Response includes `variables[]` (auto-extracted from `{{var}}` template
  references in content).
- `POST /llm-gateway/invoke` (uploader+) — invoke a registered prompt.
  Body: `{ prompt: name|prompt_id, variables, user_message?, version?,
  model_pref?, max_tokens?, pii_policy? }`. PII policies: `redact` (default,
  PII replaced with `[KIND]`), `reject` (409 if PII detected), `allow`.
  Returns `{ response, prompt_id, model_used, latency_ms, prompt_tokens,
  completion_tokens, cost_estimate_usd, pii_redactions[], succeeded, error }`.
- `POST /llm-gateway/scan-pii` (uploader+) — diagnostic; scan text for
  PII without invoking the LLM. Returns `{ matches[], redacted, match_count }`.
- `GET /llm-gateway/cost-summary` (viewer+) — cost aggregation. Query
  params: `since` (date), `until` (date, default today), `group_by`
  ∈ `caller | model | day | user | prompt_id` (default `caller`).
  Default range: last 7 days. Returns `{ since, until, group_by,
  total_usd, total_calls, buckets[] }`.

### Changed
- **`llm_call_log` augmented** (additive, back-compat): added nullable
  `prompt_id UUID` column referencing `prompt_registry(prompt_id)`. NULL
  for legacy callers; populated when invocation goes through the Gateway.
- New indexes on `llm_call_log` for `(caller, day)` and `(user_id, day)`
  to support cost-summary queries efficiently.

### PII patterns (initial set)
- email — `[\w._%+-]+@[\w.-]+\.[A-Za-z]{2,}`
- ssn — `\b\d{3}-\d{2}-\d{4}\b`
- phone_us — US phone formats
- credit_card — 13-19 digit candidates, then Luhn-validated

### Template substitution
- Mustache-style `{{var}}` (with optional whitespace inside braces)
- **Single-pass substitution** — variable values are inserted verbatim and
  NEVER re-rendered (blocks template injection from caller-controlled values)
- Missing variables → 400 with the missing-key list

### Migration notes for frontend
- New surface (when ready): **Cost dashboard / observability admin** for
  Antigravity. Wire `GET /llm-gateway/cost-summary?group_by=caller` to a
  bar chart, `?group_by=day` to a sparkline. List prompts with `GET
  /llm-gateway/prompts` for an admin "registered prompts" view.
- Existing chat surfaces are unaffected — invoke via the Gateway is opt-in
  for callers that want versioned prompts; legacy `chat_with_telemetry`
  continues to work.
- Migration 054 must run on prod before this surface goes live.

## 2026-05-09 — SPEC_027 Source Registry + Quality Scoring

### Added
- `POST /sources` (uploader+) — register source. Idempotent on `source_id`.
  Body: `{ source_id, display_name, tier (1-4), kind (free|paid|internal),
  base_url?, description?, license_status?, license_renewal_at?,
  rate_limit_per_min?, usage_profile? }`.
- `GET /sources` (viewer+) — list with filters: `tier`, `kind`, `active`.
  Each source includes its `latest_quality` (the most recent quality row).
- `GET /sources/health-summary` (viewer+) — aggregate: `{ total_sources,
  active_count, scored_count, mean_overall_score, bottom_5[] }`.
- `GET /sources/{source_id}` (viewer+) — single source + latest quality.
- `PATCH /sources/{source_id}` (uploader+) — update display_name,
  description, active, license_status, license_renewal_at,
  rate_limit_per_min, usage_profile.
- `GET /sources/{source_id}/history` (viewer+) — quality time series
  (last N rows; default 100).
- `POST /sources/{source_id}/recompute` (uploader+) — compute fresh quality
  row, update `latest_quality_id` pointer.

### Quality scoring (5-dim)
- `coverage` (weight 0.25): tier-default until SPEC-028 wires real ground truth
- `latency` (0.20): p95 lag from `evidence_records.retrieved_at` over last 1000
- `predictive_accuracy` (0.30): default 0.5; SPEC-028 will populate
- `stability` (0.15): stub from `active` flag; future: connector lifecycle log
- `license_health` (0.10): `expired` → 0; `rate_limited` → 0.5; `active` →
  1.0 (linearly degraded in 30-day renewal window); `not_applicable` → 1.0
- `overall_score = Σ (weight × dimension)`, clamped [0, 1]

### Migration notes for frontend
- New surface: **Source Health admin** (spec §9.3). Wire
  `GET /sources/health-summary` for the headline strip,
  `GET /sources` for the per-source table (showing tier, license_status,
  overall_score, mean latency p95). Bottom-5 in summary highlights
  degraded sources.
- Migration 055 must run on prod before this surface goes live.

## 2026-05-09 — SPEC_029 Framing Triggers

### Added
- `POST /framing-triggers` (uploader+) — create trigger config. Body:
  `{ name, kind: 'threshold'|'cluster'|'calendar', config{...},
  assignee_user_id? }`. Each `kind` has its own whitelisted `config` shape;
  unknown keys rejected with 400 (R8 — config injection guard).
- `GET /framing-triggers` (viewer+) — list with `kind`, `is_active` filters
- `GET /framing-triggers/{trigger_id}` (viewer+)
- `PATCH /framing-triggers/{trigger_id}` (uploader+)
- `DELETE /framing-triggers/{trigger_id}` (uploader+) — 204
- `POST /framing-triggers/tick` (uploader+) — evaluate ALL active triggers
  now; returns per-trigger result. Failures isolated (one crash doesn't
  abort others).
- `POST /framing-triggers/{trigger_id}/evaluate` (uploader+) — evaluate one
- `GET /framing-triggers/{trigger_id}/fires` (viewer+) — recent fire log

### Trigger kinds
- **threshold**: fires on signal with `materiality_score >= min_score`
  (configurable, sane floor 50). Optional `claim_types`/`entity_types`
  whitelist. Each signal can fire at most once per trigger (dedup).
- **cluster**: fires when ≥`min_cluster_size` signals share `entity_field`
  within `rolling_window_days`. Optional `min_total_materiality` threshold.
  Per-(trigger, entity) dedup within window.
- **calendar**: fires when `NOW() >= next_fire_at`; advances `next_fire_at
  += interval_days` on success. Idempotent within interval.

### Auto-created brief shape
Each fire creates a `decision_briefs` row in `draft` state via SPEC-023:
- `trigger_kind` set to one of `threshold|cluster|calendar`
- `trigger_signal_ids[]` populated (empty for calendar)
- `trigger_metadata` carries trigger context (trigger_id, name, threshold,
  cluster size, etc.)
- `evidence_refs` includes `{type: 'signal', id}` per matched signal
- `owner_user_id` set from trigger.assignee_user_id (or null = unassigned)

### Migration 059 (additive)
- New tables `framing_triggers` (config) + `framing_trigger_fires` (event log)
- Conditional FK to `decision_briefs(brief_id)` (works regardless of deploy order)

### Migration notes for frontend
- New surface: trigger admin (lower priority — backend-driven for now).
  Eventually wire `GET /framing-triggers` to a tiny config UI.
- The Inbox surface (already built by Frontend Claude) automatically picks
  up auto-created briefs since they land in `draft` state visible to GETs.
- For the "why was this brief auto-framed?" tooltip on each brief card:
  read `brief.trigger_metadata` (already exposed in the brief payload).
